# Deploying to Render (SQLite + persistent disk)

This app ships a `Dockerfile` and a `render.yaml` blueprint. The SQLite
database lives on a **persistent disk**, so data survives deploys and restarts.

> A persistent disk requires a **paid** Render instance (the free tier has no
> disk). See current pricing: https://render.com/pricing

## Option A — Blueprint (recommended, uses `render.yaml`)

1. Push this repo to GitHub (already done).
2. In Render: **New → Blueprint**, connect the repo, and let it read
   `render.yaml`. It creates a Docker web service `gokul-gruh-admin` with a
   1 GB disk mounted at `/var/data` and `DATABASE_URL=file:/var/data/prod.db`.
3. When prompted, set the env vars marked `sync: false`:
   - `SEED_ADMIN_EMAIL` — e.g. `admin@gokulgruh.local`
   - `SEED_ADMIN_PASSWORD` — your first-login password (change it in-app later)
   - `SEED_ADMIN_NAME` — e.g. `Kripal Dobariya`
   - `AUTH_SECRET` is auto-generated by Render.
4. Click **Apply**. First deploy builds the image, runs
   `prisma migrate deploy`, seeds the admin, and starts the server.
5. Open the service URL and log in.

## Option B — Manual (no blueprint)

1. Render → **New → Web Service** → connect the repo → **Runtime: Docker**.
2. Instance type: **Starter** or higher (needed for a disk).
3. **Add a Disk**: mount path `/var/data`, size 1 GB.
4. **Environment** → add:
   | Key | Value |
   |-----|-------|
   | `DATABASE_URL` | `file:/var/data/prod.db` |
   | `AUTH_SECRET` | a long random string (≥32 chars) |
   | `SEED_ADMIN_EMAIL` | `admin@gokulgruh.local` |
   | `SEED_ADMIN_PASSWORD` | your first-login password |
   | `SEED_ADMIN_NAME` | `Kripal Dobariya` |
5. Create the service and deploy.

Generate a strong `AUTH_SECRET` locally with:

```bash
node -e "console.log(require('crypto').randomBytes(48).toString('hex'))"
```

## Notes

- **Migrations/seed run at container start**, not at build — the disk is only
  mounted at runtime. Seeding is idempotent: it never overwrites an existing
  admin, so a password you change in-app is preserved across deploys.
- **HTTPS**: Render serves the app over HTTPS, which the `secure` session
  cookie requires in production.
- **Backups**: the SQLite file is at `/var/data/prod.db` on the disk. Use
  Render disk snapshots (or periodically download the file) to back it up.
- **Scaling**: SQLite means a single instance. Do not scale this service to
  multiple instances — they cannot share the one SQLite file. For multi-instance
  scaling, switch the Prisma datasource to Postgres.
